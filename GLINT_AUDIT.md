# Glint stabilization audit

The initial production build completed. An isolated baseline Electron launch registered the shortcut, started with zero windows and loaded the assistant and preload on activation. Main TypeScript passed. Renderer TypeScript failed on four settings errors. No automated test command existed. A recovery copy of the original uncommitted IPC file and scratch script was taken and hash-checked before editing. The private local .env and the user's profile were outside the test inputs.

The durable recovery copy is under %LOCALAPPDATA%/Glint-Audit/checkpoints/8cdb11f-81a6c51ff5be4515a2144a57d6c6f9d6. It contains HEAD.txt, the original scratch script, and ipc.ts.dpapi. The IPC copy contains the original working-copy Git blob, encrypted with Windows ProtectedData (CurrentUser). Decryption and byte equality were verified. It can be recovered to a separate file under the same Windows account. Keep that copy private.

## Remaining product and engineering findings

1. **P0 release prerequisite.** Key rotation and a clean live-provider qualification remain outstanding. The configured model list comes from repository history. Automated results cannot establish account entitlement, availability or response quality.
2. **P1 core L2 reliability.** Desktop-root enumeration omitted the fixture even when direct UIA lookup by handle returned its visible rectangle. A global search can also match the same label in another window. Visibility of the next label can advance a step without a user transition. The current verify loop can repeatedly send images during a stalled session. These issues affect trust, latency and provider usage.
3. **P1 multi-display and release coverage.** Capture callers use the primary display while UIA can locate another display. There are two displays on the test host. Native DIP conversion replaced manual scale arithmetic. One two-display fixture passed the center-alignment check. Physical pointer pass-through, negative-origin alignment, hot-plug recovery and installed notification behavior need release evidence.
4. **P1 usability.** First launch is tray-only. Settings is easier to discover once a missing-key error appears. The floating body supports pointer activation with limited keyboard semantics. Startup, theme and always-on-top remain product decisions. There was no timed novice study, so two-minute independent onboarding remains unverified.
5. **P2 structure and coverage.** GuidanceSessionService owns mutable state, timers, native notifications, window operations and provider calls. Session reads are loosely typed and goal history remains process-local. The service registry includes placeholders. No installer, provider contract suite, failure-rate instrumentation or representative language corpus existed at baseline. Several model fallback names carry unvalidated performance labels in the UI.
6. **P2 speech readiness.** The interface covers capture lifecycle and transcript ingress. Audio permission UX, provider selection, transcript review, deduplication and recognition accuracy have no implementation or field evidence.

See GLINT_IMPLEMENTATION_PLAN.md for ordered work and acceptance gates. The stabilization did not establish L3, click detection, general timer functionality or real-world speech support.
